# 无限大盘 P2P 文件传输系统 安全建设管理

## 第一章 安全方案设计

**第一条** 系统新建、改建、扩建项目应进行安全需求分析与方案设计，方案内容至少包括：

1. 系统定级与保护要求（当前为第一级）；
2. 身份鉴别、访问控制、数据保护、审计等安全功能设计；
3. 部署环境（云主机、网络端口、域名）及安全组策略设计；
4. 数据备份与恢复方案。

**第二条** 安全方案应经安全负责人审批后方可实施，方案及审批记录归档保存。

**第三条** 本系统当前安全设计基线（作为设计依据）：

| 方面 | 设计措施 |
|---|---|
| 身份鉴别 | 管理后台口令 scrypt+盐哈希存储；设备令牌、主机令牌一次性签发；激活码一次性且 24 小时有效 |
| 访问控制 | 共享目录三权限（下载/上传/删除）按设备授权；角色分管理员/普通用户 |
| 数据保护 | 凭证数据 AES-256-GCM 加密落盘；密钥（ENC_KEY）存服务器环境变量，与数据分离 |
| 通信安全 | 文件传输走 WebRTC DTLS/SRTP 加密通道；信令服务后续升级 HTTPS 加密 |
| 审计 | 服务日志记录激活、配对、管理操作等关键事件 |

## 第二章 软件开发安全

**第四条** 开发过程应遵循以下安全编码要求：

1. 使用参数化查询或结构化数据接口，避免注入类漏洞；
2. 口令不以明文存储或传输，必须哈希（scrypt）后存储；
3. 敏感信息（令牌、密钥）禁止写入日志、前端代码或版本库；
4. 对外接口做输入校验与长度限制，拒绝异常数据；
5. 依赖组件及时更新，修复已知高危漏洞。

**第五条** 版本号统一管理：服务器版本号（server.js SERVER_VERSION）与客户端版本号（Android version.dart / 电脑端 version.dart）同步维护，升级包发布时三方版本一致。

**第六条** 开发环境与生产环境隔离，开发调试不直接操作生产数据；测试数据不得包含真实用户凭证。

## 第三章 测试与验收

**第七条** 新版本上线前须完成以下测试并形成记录：

1. 功能测试：激活、配对、共享、传输、管理后台等核心功能；
2. 升级兼容性测试：旧版本客户端可正常提示升级、新版本可正常回连；
3. 安全测试：非法凭证访问、越权操作、异常数据输入；
4. 加密数据迁移测试：旧明文数据文件升级后可正常解密读取。

**第八条** 验收要求：

1. 全部测试用例通过（或经批准的例外项）；
2. 升级包 MD5 校验值随包发布，客户端下载时校验一致；
3. 验收结果由安全负责人确认签字后归档。

## 第四章 上线审批与发布

**第九条** 发布流程：

1. 开发完成并自测通过；
2. 执行第三章规定的测试与验收；
3. 构建安装包并计算 MD5，上传至服务器下载目录；
4. 经安全负责人审批后对外发布（客户端自动检测升级）；
5. 发布后观察服务器日志与运行状态不少于 24 小时。

**第十条** 发布记录（版本号、时间、发布人、变更内容、MD5）归档保存，作为审计追溯依据。
