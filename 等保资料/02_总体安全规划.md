# 无限大盘 P2P 文件传输系统 总体安全规划

## 一、规划目标

围绕系统第一级安全保护要求，建立"管理制度 + 技术措施 + 运维保障"三位一体的安全保障体系，确保系统运行安全、数据完整可用，满足 GB/T 22239-2019 第一级基本要求。

## 二、安全保护范围

| 对象 | 范围 |
|---|---|
| 物理环境 | 阿里云 ECS 云主机（由云服务商提供物理安全） |
| 网络通信 | 服务器 3000 端口服务、OSS 升级包分发通道、WebRTC P2P 通道 |
| 应用系统 | 信令服务器（Node.js）、手机端 App、电脑端 |
| 数据 | 凭证数据（激活码/令牌/配对码）、共享配置、授权数据、升级包 |

## 三、安全策略框架

### 3.1 管理安全策略
- 建立安全管理制度体系，明确岗位安全职责（见《安全管理制度》《安全管理机构》）
- 人员安全管理：录用、培训、离岗（见《安全管理人员》）
- 建设安全管理：开发、测试、验收（见《安全建设管理》）

### 3.2 技术安全策略
- **身份鉴别**：管理后台口令（scrypt+盐哈希存储）、设备令牌（一次性签发）、主机令牌、激活码（一次性、24 小时有效）
- **访问控制**：共享目录三权限（下载/上传/删除）控制、角色二态化（管理员/普通）、设备绑定关系
- **数据保护**：凭证数据 AES-256-GCM 加密落盘，密钥（ENC_KEY）与数据分离、仅存于服务器环境变量；升级包 MD5 全链路校验
- **传输安全**：文件传输走 WebRTC DTLS/SRTP 加密通道；P2P 直传文件不经过服务器

### 3.3 运维安全策略
- 每日自动备份敏感数据（保留 30 天），备份恢复预案见《安全运维管理》
- 运行日志审计：服务日志记录关键操作（激活/配对/管理操作）
- 版本变更管理：升级包经 MD5 校验后发布，发布流程规范化

## 四、实施计划

| 阶段 | 内容 | 状态 |
|---|---|---|
| 一期（已完成） | 去手机号改造（不再收集个人信息）、凭证加密落盘、自动备份、升级包校验 | ✅ 已完成 |
| 二期（进行中） | HTTPS 通信加密（域名 wuxiandapan.com + TLS 证书）、管理文档体系 | 部分完成 |
| 三期（持续） | 制度宣贯、定期备份恢复演练、安全自查 | 持续开展 |

## 五、经费与资源保障

- 云资源：阿里云 ECS + OSS（既有预算）
- 证书：Let's Encrypt 免费证书或阿里云免费证书（无额外成本）
- 人力：系统开发运维人员兼任安全管理岗位，按本套制度执行

## 六、评审与修订

本规划每年评审一次，或发生重大变更（业务模式、系统架构、定级变化）时及时修订。
